## C01–C20

| 编号 | 约定主题 | 采用约定 |
| --- | --- | --- |
| C01 | 匿名和登录同时存在 | 所有填写者先登录；允许匿名的问卷可选择匿名提交，作者界面和 API 不返回其账号标识；关闭匿名时按实名账号关联提交 |
| C02 | 匿名情况下防重复 | 服务端根据用户和问卷生成稳定的 HMAC 去标识化键，用于防重复及独立人数统计；不向作者返回该键 |
| C03 | 题型和必答 | 内部使用 single、multiple、text、number 四个类型；各类型可提供 required，单选必答为原文明确要求；实际到达题的正 minSelections 或 minLength 也必须执行，required=false 不能覆盖正下限 |
| C04 | 重复填写开关 | allowMultipleSubmissions 默认 false，发布前可设置；发布后冻结，避免旧答卷的唯一性语义变化 |
| C05 | 每次填写保存 | 第一阶段保存每次成功提交的有效答卷；未提交过程保存在当前页面内存，不实现跨刷新草稿保存 |
| C06 | 生命周期 | draft 可以编辑；published 可以填写；closed 停止填写；过期是由截止时间计算的有效状态，保留原始状态和数据 |
| C07 | 发布后修改 | 第一阶段冻结发布内容，只允许关闭；第一周就实现按问卷版本读取定义的入口，第二周若允许改题，再沿该入口保存历史版本，不能覆盖旧答卷对应的定义 |
| C08 | 跳转方向 | 第一阶段采用跳到序号更大题或 END 的无循环模型，覆盖原文示例；方向和循环在原文中未规定，此为公开的范围约定，若正式说明要求回跳则沿引擎扩展并补重访及终止测试 |
| C09 | 多规则冲突 | 每题规则按显式顺序匹配，第一条命中生效；没有命中则进入下一题，最后一题默认 END |
| C10 | 多选条件 | 支持 containsAny、containsAll、equalsSet；选项顺序不影响结果，条件集合必须非空 |
| C11 | 数字条件 | 支持 eq、lt、lte、gt、gte、between，between 两端均包含 |
| C12 | 跳过题和必答 | 只校验实际到达路径上的题；被跳过的必答题不阻塞提交 |
| C13 | 返回修改答案 | 改变前面答案后重新计算路径，清理已不在路径上的答案；后端提交时再计算一次并拒绝路径外答案 |
| C14 | 关闭与在途提交 | 提交通过最终准入检查后允许完成；关闭后新进行准入检查的请求拒绝。不能声称关闭和答卷插入是跨集合原子操作 |
| C15 | 截止时间 | 数据库存 UTC，页面按 Asia/Shanghai 显示；准入检查时 now >= closesAt 即拒绝，提交前进入页面不保留提交资格 |
| C16 | 统计口径 | 仅统计成功落库答卷；显示作答份数及独立填写人数；数字平均按有效数字答案计算，空答和跳过不当作 0 |
| C17 | 选项人数与重复答卷 | 单选同时提供选项作答次数和选项独立人数；同一人多次选择不同选项时，可分别计入多个选项的人数，选项人数之和可能大于总独立人数 |
| C18 | 删除和重开 | 第一阶段不提供删除已发布问卷、删除已提交答卷、重开问卷；题目删除和重排仅用于草稿编辑 |
| C19 | 空问卷 | 草稿可暂时没有题，发布时必须至少一题且定义完整 |
| C20 | 数字和文字口径 | 数字在 JSON 中用十进制字符串传输，再转 Decimal；文本去两端空白并做 NFC 规范化后按 Unicode 码点计数，前后端统一 |

## 审查后实际修订

1. 初稿曾允许“可选空答”绕过正的 minSelections/minLength。已在最终计划修订：实际到达题必须执行正下限，required=false 不能覆盖；被跳过题仍豁免。对应 T25、T27、T29、T31、T37、T45、T74。
2. 初稿自加最多六位小数，已取消；采用 Decimal128 可精确表示域，并支持合法科学计数。对应 T35、T43、T88。
3. CSRF 数据库只保存摘要，不能跨页从摘要恢复原令牌。计划改为独立 csrf_token Cookie，页面读取后发送 X-CSRF-Token，和当前会话摘要比较。对应 T87。
4. 版本读取与幂等检查顺序：按提交版本规范化并确认已成功记录，再对新提交检查当前准入；关闭或旧版本停止新提交不应破坏既有成功回执。对应 T61、T62、T86。

这些记录是实际方案审查和修订；相应最终代码及自动/浏览器回归已核实，见tests.md。

## 公开边界

匿名限定为问卷作者不能从正常界面和 API 获得账号身份；持有 HMAC 密钥和账号数据的系统管理者仍可能建立关联。第一阶段仅支持向后续题或 END 的跳转，是公开的范围约定；原文未规定方向，也没有明确要求回跳。若教师要求其他语义，记录变更并扩展引擎及终止测试。

未提交过程不跨刷新保存；不提供已提交答卷删除、已发布问卷删除和重新开启；这些都属于项目约定，不能宣称为教师禁止。资源上限必须公开并有统一修改位置，不能使已保存的合法校验条件悄然失效。当前实际题量、选项、文本与规则数量边界在 question_types.py 的领域常量中，前端使用对应边界；提高这些上限须同步检查前后端，不能声称只改 .env 即可生效。问卷 BSON 大小上限单独由 Settings.max_definition_bytes 配置。

## 联调中形成的具体补充

统计处理器第7参数response_filter固定本次答卷成员，数字均值采用流式高精度求和再34位除法。它们修复真实并发一致性、Decimal128中间溢出及抵消问题，回归已通过；ID列表O(n)和15MiB筛选保护是公开规模边界，超限返回503而不静默截断。新环境复现首次harness遗漏Origin触发403，修复脚本headers后完整复现通过；这是复现脚本问题，不冒称业务权限缺陷。

## 本轮再次按原文复核后的修订

1. UTC转换越界原先可能冒出500，现将时区换算纳入同一错误边界，创建/修改返回422，旧数据不变。
2. 兼容默认值原先主要是工具函数，现from_storage_survey接入真实生产读/填/统计路径，只补4个已知可选字段，不回写、不猜测未知字段。
3. 单题翻页原先仅换内容区，现整个题卡及选中题状态一起更新；整卷与单题更新时间分别显示，不宣称全局实时同步。
4. 题ID保存与寻址契约统一：path路由保留slash/percent/Unicode；all不再占用整卷哨兵；.、..、Cc/Cs在保存前拒绝。普通ID不被重新编号。

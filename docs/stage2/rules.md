# 第二阶段关键业务规则

本文件对应实际题目库、问卷绑定和统计服务。项目解释及取舍见[设计决策](decisions.md)，字段与事务见[数据库设计](database.md)。原四题型校验、跳转重放、匿名及重复策略、截止关闭和提交幂等继续使用第一阶段实现。

## 编辑稿与正式版本

创建独立题目先保存可变 `workingContent`，正式版本号为0。保存编辑稿只更新管理revision；显式“保存为新版本”才生成v1。已有版本的修改必须指出来源版本；恢复旧版也生成新编号并保留中间历史。

任何问卷发布并引用这道独立题目后，`hasPublishedUsage` 永久为true，关闭问卷或下架版本不解除。此后后端拒绝普通稿覆盖，内容变更必须随新版本一起保存。即使尚未被发布使用，普通稿变化也不会自动进入已经选定v1的问卷；问卷始终使用明确正式版本。

版本内容包括标题、题型、必答、选项和校验。实例ID、题序、跳转属于问卷。内容规范化沿用原领域校验器；数字以精确十进制字符串传递并最终按Decimal128存储答案，不经浮点近似。

## 引用、快照与升级

从题库选题时请求必须给出versionId，服务端读该版本、检查权限和可选状态，生成新实例ID并固化内容。前端不能指定owner/root或提交任意快照冒充公共题。两次独立选用可以生成两个实例；同一请求网络重试则返回原操作结果。

题库出现v2不自动替换任何问卷。草稿手动升级时保留实例ID，替换内容和来源引用，重新验证整卷规则。目标新版删掉了跳转条件的选项或改变题型而使规则无效时，整次更新失败并报告定位，不静默删除规则。已发布问卷禁止升级。

原整卷PATCH和单题PATCH也经过内容hash检查：已关联实例可以改问卷内跳转和位置，但不能在保留v1引用的同时覆盖标题、选项或约束。直接新建的本地题仍可编辑，在保存为库题或发布时登记正式来源。

## 共享、公共题和派生

私有题所有者管理原题；公共题由当前管理员维护，创建者记录实际账号。授权挂在独立questionId，包含正式版本及后续正式版本，不包含workingContent，也不覆盖root家族。共享者和接收者都可继续选用，共享不授予原题修改、他人问卷管理或答卷读取权限。

派生是完整复制内容到自己的新题目及版本，继承root并记录直接来源。派生正文不依赖源题仍可访问；展开来源才检查源权限。撤权后可以从本人已持有的问卷快照派生，不重新读取撤权源正文。

批量派生上限五个明确的本人实例；同源版本及内容相同的快照去重成一个副本并返回映射。整批事务和幂等保护，失败不留半批结果。默认不替换原引用；特别是已发布实例保持原样。

## 归档、版本下架和更新提示

整题归档停止新增选用；版本下架只改变独立可选状态。旧问卷快照及自己的派生内容继续有效。非维护者不能借历史列表或版本详情重新获取下架来源；仍可查看自己问卷已有快照。

更新提示比较最新可选正式版本与本人收藏选定版或每一个已用实例。不能用“我用过的最大版本号”掩盖仍在使用的v1；最高版本下架时提示也不能指向已不可选的版本。无自动升级和推送。

## 个人题库与使用记录

题库采用个人收藏加标签，公共题库是公开题的视图。本阶段无整库授权、共享容器或整库批量选用。每题可以有多个本人标签，修改标签只改本人bookmark；移除不删除原题、版本、引用或答案。

已有收藏仅改标签时保留原selectedVersionId，包括null；维护者归档题目或停用版本后仍可整理。归档题不能新增收藏或换收藏版本。非维护者无可查看来源时，收藏接口拒绝且整个写入回滚；独立个人标签重命名不读取来源，仍可整理。统计接口也不向未持有快照的普通用户返回停用版本内容；维护者与本人合法快照保留统计能力。

本人使用明细可以显示本人的问卷标题、状态和回答数。题目维护者可额外查看其他问卷的历史累计N，按surveyId去重，不能按他人身份或时间切片，也不返回他人标题和答案。普通选用者没有这项计数权。它不扩展跨问卷答卷统计权限。

usage从迁移时存量和之后实际选用登记，移除实例或升级不消除曾使用事实。迁移前已经消失的历史不可补造，observedAt不伪装成原始使用时间。当前不新增整卷删除功能，删除数只能基于真实事件。

## 并发、回滚与重试

管理写入同时匹配资源权限、状态和revision。两个页面用同一revision保存，只能一个推进，另一个收到409；前端应保留输入供比较，不能自动改revision后覆盖。

题库内容保存从请求发出到回读完成阻止继续编辑及切换题目；失败后解锁并保留输入。请求模型拒绝无法编码的Unicode及超过BSON int64的修订号/定义版本，分页同时限制page及pageSize，避免数据库编码溢出。

版本与指针、状态和回执同事务；失败时编号递增和revision也回滚。事务不是“失败后留下孤儿再清理”。选用与归档、下架、撤权在共同控制文档上真实写guard，产生明确的提交先后；普通读取不持有应用级编辑锁。

幂等键限定用户及操作。成功的同键同内容返回原结果，同键不同内容拒绝；失败事务不留成功回执。请求重试要保留原requestKey及参数，不能为每次网络重试换新键。瞬时数据库冲突可以按驱动策略重试，业务revision冲突不能静默重试覆盖。

## 跨问卷统计

统计的统一入口先解析可统计问卷范围，首版仅本人问卷，再匹配精确版本和 `(surveyId, definitionVersion, instanceId)`。同题不同版本、同源派生、独立同名或同义题不自动合并。题目可见或公共可用不等于有权统计他人答案。

| 指标 | 口径 |
| --- | --- |
| answerCount | 目标实例的非空答案数；一份答卷两个实例分别回答计2 |
| responseCount | 至少有一个目标答案的不同response ID数量；同份答卷不因两实例重复计 |
| surveyCount | 有目标回答的不同问卷数 |
| options | 单选/多选每个选项的选择次数，多选总次数可超过回答数 |
| average/min/max | 所有合法数字答案的精确汇总，0有效，空答和跳过排除 |
| distribution | 数字值频数分组，按数值排序及分页，不返回答卷级明细 |
| distinctValueCount | 非空答案不同值数量；文本仅返回数量，不暴露跨卷原文 |
| bySurvey.respondentCount | 该卷目标答案的稳定respondentKey去重数量，表示填写账号数；缺稳定键时为null |

本系统匿名也须登录，respondentKey由问卷ID和账号ID的HMAC生成，因此同卷匿名/实名切换、重复提交和两实例可以统一去重。跨卷键不同，不提供全局独立人数，也不枚举账号反推匿名身份。

原有单卷填写内容查询保持；新跨卷入口仅汇总，不做合并答案明细或导出。若来源已归档或撤权，用户仍可统计自己合法持有的快照回答，不能因此浏览源题历史。

同一次请求先固定答卷ID成员，后续总量、分布、精确平均及逐卷统计共用集合。新答卷在下一次刷新纳入。检查本人所有已答定义的映射完整性；发现缺历史定义或缺来源时返回MIGRATION_INCOMPLETE，不把漏算显示为0。未答空草稿不阻塞统计。

数字使用高精度流式求和后除以总回答数，避免极大值溢出及正负抵消丢精度；不对各卷平均值再平均。查询条件超过15MiB时明确拒绝，不静默截断。该方案有随答卷数增长的成员内存和聚合成本，不宣称适用于无限数据量。

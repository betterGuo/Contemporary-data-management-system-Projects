# 第二阶段设计决策

记录日期：2026年10月26日。

M0将需求讨论收敛为以下规则，第二阶段代码已据此落实。决策依据见[需求范围](requirements.md)及[完整执行计划](../../第二阶段执行计划.md)，实际验证见[实施状态](status.md)。这些是对原文未明确部分的项目解释，后续变更须同步修改影响分析与测试。

## D01 可变编辑稿与不可变正式版本

题目管理记录持久保存 `workingContent`、内容摘要、编辑基准版本和并发 `revision`。独立创建时可尚无正式版本；“保存编辑稿”和“保存为新版本”是不同的后端动作。前者在允许时更新当前稿、不推进内容版本号；后者生成不可变版本、推进最新指针并同步管理记录。

问卷只能选用正式版本并保存快照，不读取编辑稿。任何问卷发布时引用过该独立题目，即将 `hasPublishedUsage` 永久置为 true；此后普通编辑稿覆盖被拒绝，内容保存必须随新版一起提交。关闭问卷、移除其他草稿引用、下架版本都不解除该状态。此规则用于统一原文第三条的保护要求与第六条的编辑选择，并比仅冻结问卷快照更严格。

发布标记与问卷发布同事务更新；普通稿更新同时检查 `hasPublishedUsage=false` 和预期 `revision`。不能先查 usage 再无条件保存，否则编辑与发布会产生竞态。正式版本内容始终不可覆盖，无变化的普通保存不制造新版本。

## D02 题库选择个人收藏和标签分组

采用讨论中的 B 方案：每人有自己的题目管理空间，通过个人收藏和多个标签整理；公共题库是公开题目的视图。不建立可共享题库容器，不做整库授权、一键整库选用、嵌套目录或维护组。

使用 `question_bookmarks` 保存 `userId + questionId + tags + selectedVersionId` 等个人状态。共享题的标签属于整理者本人，不能写回源题造成他人的分类变化。移除收藏或标签不删除题目、版本和问卷引用，也不授予或撤回源题权限。

将来升级为共享容器仍需容器身份、成员映射和授权改造，不承诺给标签加一个标记即可零迁移完成。

## D03 共享覆盖正式版本 不继承根权限

共享授权挂在独立 `questionId`，允许指定用户使用该题现有和后续正式版本，直到授权撤回；不共享 `workingContent`，不自动升级问卷。共享接收者只能选用或派生，不能编辑原题、管理其授权或查看他人答卷。

`rootQuestionId` 相同不产生授权继承。原题所有者不能因此读取接收者派生题的正文、统计或维护信息。用户身份来自服务端会话，写入条件仍带资源权限与状态，不能依赖客户端 owner 字段或 MongoDB 文档校验代替鉴权。

搜索只在自己的、获授权共享的和公共题目内执行，先限定范围再搜索、计数和分页。文字相似只影响查找，不自动选用、合并身份或合并统计。

## D04 使用明细与受限历史计数

本人问卷使用情况可展示本人有权读取的标题、状态和回答信息。题目所有者或公共维护管理员另可获得“其他 N 份问卷曾使用”计数，普通使用者不可读取该维护指标。计数不包含他人标题、ID、所有者、时间或答案，也不提供按他人身份/日期切片查询。该权限是明确授予的维护能力，不以“聚合数字天然无披露风险”为理由取消授权。

新增 `question_usage` 记录真实选用过的关联，并冗余问卷所有者用于权限及去重筛选。唯一关联包含问卷、问卷定义版本、实例和题目版本；N 按不同 `surveyId` 去重，同卷双实例、多次选用或版本升级不重复计为多份问卷。当前引用仍以问卷 `questionRefs` 为准，usage 负责保留移除后的历史，两者在相关操作中同事务更新。

累计起点是迁移登记时仍存在的关联与之后观察到的使用，迁移记录不伪造首次使用时间；迁移前已消失的问卷不能补造。现系统不新增整卷删除接口，未来只有保存了真实删除事件才能显示“其中已删除 X 份”。移除实例或关闭问卷不等于删除问卷。

## D05 精确版本与独立统计范围

题目身份由 ID 与来源确定，不由文字决定。独立题目 `questionId`、正式内容 `questionVersionId`、来源根 `rootQuestionId`、直接来源 `derivedFromVersionId` 和问卷实例各有职责。旧问卷 `questions[].id` 及答案里的 `questionId` 沿用实例含义，不改编号。

默认跨卷仅汇总同一个精确正式版本；同题不同版本、同源派生题、独立创建的同名或同义题分别统计。root 用于溯源，不作为默认合并键。答案与来源按 `(surveyId, surveyDefinitionVersion, instanceId)` 匹配，不能只靠分离的 ID 列表拼接。

独立 `resolve_statistics_scope(actor)` 首版限定本人问卷，所有计数、均值、分布及来源分列统一服从这一范围。维护者获得他人使用 N，不扩大其答卷统计权限。今后改变范围入口仍须补权限和统计验证，不能视为无需检查的单点替换。

## D06 恢复保留完整历史

恢复采用“旧内容生成新版本”，记录实际来源版本和恢复原因，最新指针向前推进。保留全部中间版本及原问卷，不通过覆盖正文、删除历史或倒退最新指针来伪装恢复。修订也从明确的来源版本开始，不在冲突后静默换成最新来源。

## D07 快照派生和显式实例升级

问卷保存正式版本引用和完整内容快照；版本正文包含题型、标题、必答、选项及校验，题序、实例 ID 和跳转属于具体问卷。关联版本的内容不能通过整卷或单题更新修改后仍声称引用旧版本。应用新内容时，先生成正式版本或自己的派生题，再显式升级草稿实例并复核跳转；已发布问卷不可升级。

派生创建新的题目身份、本人所有权、完整内容和版本，继承 root 并记录直接来源；正文读取与鉴权仅依赖派生题自身。来源字段不参与正文加载和授权继承，展开来源时单独校验权限。

撤回共享后允许从本人既有问卷快照创建独立副本，不重新读取撤权源内容。首版批量上限五个明确的本人实例，按来源版本及内容摘要去重，返回实例到副本的映射。批次事务与请求幂等保护，失败整体回滚；默认只生成副本，不改变问卷引用。需要替换的草稿走额外的明确操作，已发布实例永不替换。

## D08 公共题维护与更新提示

公共题由管理员维护，普通用户仅选用和派生。创建者和操作者记录真实用户 ID，角色不是创建者身份。首次管理员由受控本地命令按明确账号授予，不把首个注册者或普通演示账号自动升级；注册 API 不能指定角色。管理员维护公共题也不意味着可以管理他人问卷或读取其回答。

公共与私有题共用题目及版本结构，公私可见性与单选/多选等题型字段分开。公共可读编号如设置，保持跨版本稳定，不把 v1 编入题目的身份。

有新版本时仅提示，不推送或自动替换。比较最新可选正式版本与本人收藏选定版本或每一个已用实例；不能用“我用过的最大版本号”掩盖仍在使用的旧实例。更新元信息也须先检查源访问权限。

## D09 汇总指标和匿名人数口径

跨卷提供回答次数、有回答的答卷数、来源问卷数、选项/数值分布及数字精确汇总。文本题提供回答次数和不同规范文本数量。跨卷不提供合并答卷明细表或导出；原有单卷查看所有填写内容的功能继续保留。

同一版本在同卷出现两次时，两条有效答案计两次回答，同一 response 只算一份答卷。逐卷人数按目标题目相关回答的稳定 `respondentKey` 去重，标签采用“本卷去重填写账号数”。本系统匿名填写仍需登录，该键由问卷 ID 和用户 ID 的 HMAC 生成，所以匿名/实名切换、重复填写和两个实例不会把同一账号重复算成人。

不同问卷的键不同，不合计为跨卷独立人数，也不枚举用户反推匿名身份。缺稳定键的异常历史数据标为不可确定，不以次数替代人数。数字0是有效答案，空答和跳过不按0计算；跨卷不能沿用“答卷数减答案行数”的未答公式而产生负数。

## D10 归档与版本可选用状态

整题归档、某版本停止新增选用、个人收藏移除分别处理。`question_versions` 正文不改写，版本可选状态放独立 `question_version_state`。归档或下架后不再供新增选用，已取得的问卷快照和自己的派生题继续有效；提示实际固定版本，如“当前问卷继续使用 v1”，不称“最后一个可用版本”。

下架最高编号后，更新提示只指向真正可选的版本。选用与题目归档、版本下架、授权撤回须在共同控制记录上产生真实写竞争，并与问卷快照、引用、usage 和幂等回执同事务提交。读取授权后仅写另一个文档不能视为已消除竞态。

本阶段不物理清理历史版本，也不宣称归档解决了数据增长。测试使用隔离库并清理自己创建的数据；历史使用日志及其覆盖范围作为业务数据备份。

## 实施与变更记录规则

所有决策在第一阶段代码与数据上增量落实。保留旧答案、提交幂等摘要及身份密钥；迁移只补新关联，不按文本自动合并旧题。版本保存、选用、使用登记及发布状态转换按各自业务事务处理，普通读取不持有应用级编辑锁。

实施先核对工作目录、旧测试和备份，再落实模型及事务环境。用户随后明确要求完成整个第二阶段，AI继续完成实现、迁移和验证；真实结果与设计规则分开记录，不把规则存在本身作为通过证据。

## 已确定的需求解释

详细理由见[设计决策](decisions.md)。这些规则是项目讨论结果，不冒称教师原文已明确规定。

- **版本与编辑分离。** 题目管理记录保存可变的 `workingContent`；尚未曾被发布问卷引用时，普通保存只推进管理记录 `revision`。显式保存为新版本才生成不可变版本。任何正式版本都不原地改写。曾被发布问卷引用后，后续内容保存必须与生成新版原子提交。
- **题目、版本和实例分离。** 独立题目有 `questionId`，具体内容有 `questionVersionId`，问卷每次使用有实例 ID。旧 `questions[].id` 和答案里的 `questionId` 继续表示实例，不重编号。`rootQuestionId` 仅表示来源家族，不承担授权或默认统计分组。
- **题库采用标签方案。** 个人题库是本人收藏及标签分组，公共题库是公开题目的视图。本阶段不建立可共享题库容器，不做整库共享或一键选用整库。
- **共享作用于独立题目。** 授权覆盖该题已保存及后续正式版本，不包含编辑稿，也不延伸到整个 root 家族。版本下架后停止新增选用，已有问卷仍使用原快照。
- **使用情况与答卷权限分开。** 本人可见自己的问卷标题、状态和本人范围内的回答信息；题目所有者或公共维护管理员可见“另有 N 份其他问卷曾使用”，不含他人标题、所有者、时间或答案。普通选用者没有维护者计数权限。
- **累计使用有覆盖起点。** `question_usage` 从迁移时存量及之后真实观察到的选用登记历史，N 按不同 `surveyId` 去重。移除实例不减历史数；迁移前已消失记录不推测补造。当前不新增整卷删除功能；只有存在真实删除事件时才可展示“含已删除 X 份”。
- **派生是独立内容复制。** 派生题有自己的所有权、完整内容和版本；来源字段只作溯源。撤回共享后可从本人既有问卷快照创建自己的题，首版支持最多五个实例的有界批量派生，事务及幂等保护，默认不替换原实例，已发布问卷不得替换。
- **跨卷只给汇总。** 默认筛选同一精确版本，只统计当前用户拥有的问卷，所有聚合共用独立的统计范围入口。不提供跨卷合并答卷明细或导出；原有单卷查看全部填写内容的功能保留。
- **人数名称准确。** 本系统匿名填写也须登录，稳定 `respondentKey` 可在同一问卷对重复填写和两个实例统一去重。逐卷显示去重填写账号数；跨卷显示回答次数、答卷数和来源问卷数，不把各卷 HMAC 键合计成跨卷独立人数。

公共题库、管理员维护、辅助搜索、批量快照派生和版本下架是对话中确定的实现范围或扩展，不是原文额外列出的独立必做项。它们使用同一套题目身份、版本和权限机制。

## 原系统和旧数据保护

必须继续支持注册登录、本人问卷管理、四种内部题型、可配置跳转、按实际路径校验、登录后填写、匿名及重复策略、幂等提交、截止关闭、整卷及单题统计。第二阶段不得以清库、重建演示系统或丢弃第一阶段代码来代替扩展。

旧题登记来源时采用 `(surveyId, definitionVersion, instanceId)` 定位，当前和历史定义分别核对。保留原实例、选项和规则 ID、快照、题序、发布状态、业务版本、答案值、提交幂等摘要及原身份密钥。不按标题相同自动归并旧题。迁移必须有备份、dry-run、中断续跑、重复执行和迁移前后统计核对；真实结果在 M1/M5/M9 单独记录。

第一阶段历史标签的197项和当前工作目录既有200项测试记录是不同基线，不能互相替代。本文件不将历史记录写成本轮已执行结果。

## 验证和提交要求

每个功能的验收记录须包含步骤、输入、预期输出、实际输出、结果和证据位置。除第二阶段新场景外，原文要求的创建问卷、添加题目、跳转、校验、提交和统计测试继续覆盖。并发和事务行为使用真实数据库验证，不能仅靠界面说明或 mock 宣称正确。

第二阶段最终仍提交可运行代码及 MongoDB schema/配置说明、系统与数据库/API/关键逻辑文档、测试用例及结果、完整报告。报告保留原文九项主题，并交代第一阶段设计、新需求问题、修改原因、改动范围、结构变化、程序调整、兼容性问题和旧功能保障。

AI 日志真实记录工具、提示词、得到的代码、是否修改和改动内容；报告回答 AI 帮助、错误、本人修改和本人设计四问。用户提出修改意见与用户亲自编写代码分开归属，不补造参与、测试或错误。具体文件格式和截止时间按教师通知与用户选择执行，不能从变更文档中推定。

# 需求与验收追踪

> 第一阶段正式文档。2026-10-22完整测试为200项通过、0失败、0跳过；复测方法、历史结果及证据范围见[测试说明](tests.md)和[关键验证证据](evidence/README.md)。

## 依据、范围和优先级

依据为本机保留的课程原文《大作业一第一阶段.docx》；公开仓库以本文件归纳要求，不重复上传原文件。DOCX 是课程要求来源；两周排期、第一周完整且可扩展及“清爽专业”界面为用户补充要求。R01–R21 为追踪编号，并非教师原文编号。实施约定见[关键逻辑](rules.md)与[系统设计](architecture.md)；T01–T88 和 E01–E04 是本项目验收编号，不能说成教师要求 88 个测试。

第一阶段完成用户注册登录、问卷管理、三类题型（填空区分文本和数字）、配置式跳转、分享填写、校验提交和统计。所有持久业务数据存 MongoDB，禁止关系数据库和现成问卷系统框架。前端可以简单，但必须有可操作网页。语言和框架由实现自行选择。

第二阶段必须基于第一阶段代码修改，保留核心结构、主要功能及旧数据；只有新需求明确改变的行为才调整。正式第二阶段需求尚未发布，扩展演练不能代替正式需求实现。

## 交付及变更控制

每阶段均提交可运行代码、MongoDB schema/索引初始化及配置说明；系统、数据库、API、关键逻辑文档；有步骤、输入、输出和结果的测试材料；完整项目报告及真实 AI 日志。报告必须含项目目标、系统设计、MongoDB 设计、跳转设计、校验设计、AI 使用、测试、问题和解决。

单阶段评分为 MongoDB 35、后端25、测试10、文档15、AI15；总分为阶段一30%加阶段二70%。评分权重不直接等于工时比例。DOCX未给出具体日期、提交平台、格式或命名，应按教师后续通知核实。

变更发生时记录编号、原行为、新行为、原因、代码和数据影响、兼容办法、新测试及旧基线结果。不得以第二阶段时间紧为由清库、重新编号旧题目或重做系统。
